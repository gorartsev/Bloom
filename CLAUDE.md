# BLOOM — тренировочная система

Два слоя. **Приложение** (PWA, лежит в корне) пишет данные. **Тренер** (папка `coach/`) их читает и возвращает план.

## Что читать перед работой

| Задача | Читать |
|---|---|
| Спланировать тренировку | `coach/FLAGS.md` → `coach/PROGRAM.md` → `coach/PROGRESSION.md` |
| Разобрать сессию (пришёл экспорт) | `coach/REVIEW.md` → `coach/PROFILE.md` |
| Любой разговор про нагрузку, боль, самочувствие | `coach/PROFILE.md` |
| Править приложение | `app.js`, `data.js`, `index.html`, `sw.js` |

`coach/FLAGS.md` читается **первым** при планировании. Всегда. Это память между сессиями: что держать, что не давать, за чем следить. Флаги старше трёх недель считаются протухшими, их надо либо подтвердить, либо снять.

## Цикл

```
план  →  приложение  →  тренировка  →  экспорт  →  разбор  →  флаги  →  план
```

1. Я отдаю JSON плана. Гора вставляет его в приложении: Профиль → «Вставить план от тренера».
2. Приложение показывает план на сегодня и разворачивает его в сессию одной кнопкой.
3. После тренировки: Профиль → «Скопировать данные для тренера», вставляет в чат.
4. Я разбираю по `coach/REVIEW.md`, обновляю `coach/FLAGS.md`, отдаю следующий план.

## Формат плана

```json
{
  "date": "2026-09-09",
  "session": "A · Сила после мата",
  "kind": "strength",
  "note": "После БЖЖ. Если мат был тяжёлый, режь до трёх упражнений.",
  "items": [
    { "ex": "rdl_bb",   "sets": 3, "reps": "6",    "weight": 60, "rir": 3 },
    { "ex": "pullup",   "sets": 3, "reps": "5",    "weight": 0,  "rir": 3 },
    { "ex": "ohp_db_1", "sets": 2, "reps": "8",    "weight": 14, "rir": 3 },
    { "ex": "neck_iso", "sets": 2, "reps": "20",   "weight": 0,  "rir": 4 }
  ],
  "flags": [
    "Шея: только изометрия, мост не раньше ноября",
    "Полотенце и подтягивания на хват пока не даём"
  ]
}
```

- `ex` — строго `id` из `data.js`. Выдуманный id молча провалится в подстановке названия, поэтому сверяйся с каталогом.
- `kind` — `strength` | `calisthenics` | `bjj` | `run` | `mobility`.
- `flags` перезаписывают список целиком, а не добавляются. Отдавай всегда полный актуальный набор.
- Массив планов тоже принимается: `[{...}, {...}]` или `{"plans":[...]}`.

## Формат экспорта

Приложение отдаёт `kind: "bloom-export"`: профиль, вес, флаги, нагрузка по неделям, ACWR и все сессии за 6 недель с подходами (вес, повторы, RIR).

## Приложение: как устроено

- `index.html` — разметка и все стили, темы через CSS-переменные.
- `data.js` — каталог упражнений (83 позиции), типы сессий, шкалы RPE и RIR.
- `app.js` — состояние, рендер, расчёты, обработчик событий.
- `sw.js` — офлайн. **При каждом изменении файлов поднимай `VERSION`**, иначе телефон будет держать старую версию из кэша.
- Данные: `localStorage["bloom"]`, версия схемы `v:2`. Миграция с v1 (розовый дневник) есть в `migrateV1`.
- Никаких CDN и сборки. Открыл файл, поправил, задеплоил.

## Правила по коду

- Ванильный JS, без фреймворков. Не тащить React обратно.
- `overflow-x:hidden` на `html/body` ставить нельзя, ломает `position:sticky` у шапки и таймера отдыха.
- Проверка перед пушем: `node --check app.js data.js sw.js`, дальше прогон сценария в браузере, а не «выглядит нормально».
